YourHome Maps: System Overview

1) Purpose

YourHome’s map is a decision surface, not just a visual map. Users need stable, trustworthy nearby context (homes, schools, parks, etc.) while panning and zooming across iOS/Android.

2) Architecture

  • Mobile (Expo/React Native): UI, viewport, map interactions, pin rendering.
  • API (Fastify + TypeScript): provider orchestration, ranking, dedupe, capping, caching, status output.
  • Postgres: source of truth for platform entities (users, listings, verification, entitlements).
  • Prisma: typed ORM between API and Postgres + migrations.
  • Providers: Mapbox with fallback behavior for resilience.

3) Postgres (what it is)

Postgres is a relational database server (dev at localhost:5432) that stores persistent data with constraints, indexing, transactions, and concurrency safety. API connects via DATABASE_URL.

4) End-to-end map request flow

  1. Client captures viewport bounds + term chips.
  2. Client calls batch endpoint (/directory/poi-search/batch).
  3. API normalizes terms, checks cache, queries providers, applies fallbacks.
  4. API ranks by viewport-center distance, dedupes near duplicates, caps per term.
  5. API returns items + per-term status (ok/stale/timeout/error).
  6. Client renders pins and preserves stable UX while region changes continue.

5) Why backend batch orchestration

A single backend contract avoids client-side provider chaos (inconsistent behavior, hard retries, difficult debugging). It centralizes reliability logic and improves cross-platform consistency.

6) Stability mechanisms

  • Backend: cache TTL, fallback strategy, ranking, dedupe, capping, per-term telemetry.
  • Frontend: debounce, stale-request guard, last-good-pin preservation, selection persistence, low-zoom clustering.

7) Recent blockers and fixes

  • API strict TypeScript compile errors in POI paths were patched and build now passes.
  • Mobile workspace build failed from web export path + native maps import mismatch; build flow was adjusted for native export targets in this workflow.
  • Smoke test initially failed because Postgres was down; DB was restored + migrations applied + smoke passed end-to-end.

8) Team runbook (if broken)

  1. Verify Postgres is up and reachable on 5432.
  2. Apply/check Prisma migrations.
  3. Run API and smoke test.
  4. Inspect API logs + per-term status payload for map reliability issues.

9) 30-second summary

YourHome map uses a mobile client + backend batch orchestration model. Client sends viewport and terms, API normalizes provider output with reliability logic, and Postgres/Prisma provide stable platform state. The result is predictable, debuggable map behavior at production quality.
